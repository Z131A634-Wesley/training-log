# 健身训练日志 V1 开发计划

## 目标

做一个手机上也能快速填写的中文网页：**选动作 → 带出上次的起始重量 → 调整组数 → 保存**。首页用 GitHub 风格的热力图回看训练。当前工作区为空，从头建项目，首版不迁移旧 HTML 的数据。

## 产品设计

- **记录训练。** 默认记录今天，也能选过去的日期补记。可以输入新动作，或从历史动作中选；组数默认 3，支持 `−` / `+` 和直接输入。每个动作记录名称、起始重量（kg）、总组数和可选备注。一次训练可添加多个动作，一天可保存多次训练。
- **沿用起始重量。** 选历史动作时，从该训练日期当天或之前的已保存记录中取最近一次的起始重量；同一天以保存顺序为准。比如「划船 40 kg × 4 组，备注：末组 35 kg × 12 次」，下次带出的是 **40 kg**。没有历史的动作留空；`0 kg` 可用于自重动作。编辑旧记录时保留原来的填写值。
- **热力图与历史。** 首页显示最近 52 周，每列从周一开始，手机上默认看到最近几周，可横向滚动。按当天总组数上色：`0`、`1–5`、`6–10`、`11–15`、`16+`。电脑悬停或键盘聚焦看摘要，点击或手机轻点查看当天完整记录。同一天的多次训练分开显示；历史支持补记、编辑和删除，超过 52 周的记录也能从历史列表查看。
- **备份。** 支持导出全部记录为 JSON。导入时先验证并显示训练条数，确认后替换本机记录；格式不合法或版本不支持时保留原数据。首版用备注记录降重等细节，暂不做逐组输入、模板、登录或云同步。

## 开发顺序

1. **搭建项目和数据层。** 用 Vue 3、TypeScript、Vite，沿用本机 Node 24。将页面组件、训练规则和存储模块分开。`localStorage` 存一份带版本号的文档：`{ schemaVersion: 1, sessions: [...] }`。每次训练含 ID、本地日期 `YYYY-MM-DD`、创建时间和动作列表。只保存原始记录，默认重量、历史动作和热力图都从记录计算。读取损坏数据时提示恢复，不自动覆盖；写入失败时保留表单并提示未保存。
2. **打通训练流程。** 先完成新建、保存、刷新后读取，再加历史动作建议、补记和编辑删除。保存时要求至少有一个动作，动作名非空，重量为非负数，组数为正整数。删除前确认。
3. **加热力图和备份。** 完成日期布局、颜色图例、当天详情和 JSON 导入导出。新增、编辑、删除或导入后，历史和热力图从同一份记录重新计算。
4. **准备 GitHub Pages 发布。** 提交 npm 锁文件和中文 README。GitHub Actions 运行 `npm ci`、类型检查、测试和构建；通过后仅从 `main` 发布 `dist`。Vite 使用相对资源路径 `base: './'`，适配仓库子路径。README 写清 Pages 启用方式和备份步骤，仓库只提交代码。[Vite 构建文档](https://vite.dev/guide/build.html#relative-base) · [GitHub Pages 工作流文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 验收标准

- **重量继承：** 保存「40 kg × 4 组，末组 35 kg × 12 次」，下次带出 40 kg；改成 42.5 kg 并保存后，再次记录带出 42.5 kg。补记旧日期时不会引用之后的训练。
- **日期与统计：** 同一天保存 4 组和 3 组，热力图显示 7 组，详情有两次训练；编辑或删除后立即重算。验证本地午夜和跨年日期不会错位。
- **数据可靠性：** 刷新后记录仍在；导出后可在干净浏览器中恢复；无效导入、取消导入或写入失败都不会覆盖现有记录。
- **页面与部署：** 用 Vitest 覆盖重量继承、日期聚合和备份验证；在桌面和手机尺寸下走一遍「记录 → 保存 → 回看」。发布时确认 Pages 的仓库子路径能正常加载并保存记录。
